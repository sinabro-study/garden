# 14. 모니터링·장애 대응·Feature Flag

## 기술 개념 전체 설명

### 관측

메트릭은 추세, 로그는 개별 사건, 트레이스는 요청 경로를 보여준다. release version·Git hash를 붙이면 배포와 오류 변화를 연결할 수 있다.

### 알람

사용자 영향과 긴급도를 기준으로 신호를 설계한다. 입력 오류를 WARN으로 분리하고 중복·오탐 알람을 줄여야 대응 가능한 알람이 남는다.

### 배포·복구

Feature Flag는 코드 배포와 기능 활성화를 분리해 빠르게 비활성화할 수 있다. DB 스키마 변경·데이터 이관은 플래그만으로 되돌릴 수 없으므로 호환성·롤백 계획이 필요하다.

## 이력서·포트폴리오 사례 연결

송장 미전송 장애 인지 6시간→2분 탐지, CLASS101 플래그 5초 복구, ECS 롤백 15→3분의 각각 측정 기준을 확인한다.

## Level 1~5 문제

### Level 1 · 정의

로그·메트릭·트레이스는 무엇을 보여주는가?

### Level 2 · 내부 동작

배포 태그와 알람은 어떻게 연결하는가?

### Level 3 · 장애·한계

알람 오탐과 미탐은 어떻게 검증하는가?

### Level 4 · 대안과 Trade-off

플래그 비활성화와 배포 롤백의 한계는?

### Level 5 · 실제 적용과 검증

실제 장애 타임라인·탐지·복구·재발 방지를 설명하라.
