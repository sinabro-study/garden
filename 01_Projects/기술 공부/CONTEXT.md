# 백엔드 학습 이어가기 컨텍스트

최종 갱신일 2026-11-15 (Asia/Seoul)

이 문서는 다른 컴퓨터나 새 대화에서 기존 수업을 이어가기 위한 인계 문서다.
현재 상태는 [학습진도.md](학습진도.md), 전체 일정은 [학습계획.md](학습계획.md)에서 확인한다.
기록이 다르면 최신 날짜의 실제 답변과 평가 기록을 기준으로 한다.

## 1. 학습자와 목표

- Java·Spring·DB·Cache·Queue를 기초부터 심화까지 익히고, 동일한 주문 서비스의 성능·정합성·복구를 설명하고 검증한다.
- Queue 다음에는 분산 시스템 기초 → MSA → DevOps → SRE → Infra 심화 순서로 이어간다. Linux·네트워크·Docker 기초는 앞선 실습에 필요한 시점에 다룬다.
- SAP에서 사용한 주 5시간과 4주 단위 조정을 기본값으로 적용한다. 핵심 과정은 1~30주, 확장 과정은 31~60주다.
- 한국어로 설명한다. 새 용어는 쉬운 정의와 구체적인 사례를 먼저 제공한다. JVM, HTTP 요청, DB 잠금, 캐시 무효화, 메시지 전달처럼 순서와 경계가 중요한 개념에는 흐름도를 넣는다.
- 문장마다 줄을 나누고 같은 주제의 문장 사이에는 빈 줄을 넣지 않는다. Markdown 표에서는 한 행에 한 줄을 사용하며 표 안에 빈 줄을 넣지 않는다. 셀의 줄바꿈에는 `<br>`을 사용하고 세로줄은 이스케이프한다. 저장 후 헤더·구분선·열 수를 확인한다.
- 공식 문서로 뒷받침할 때 이번 수업에 필요한 부분을 한국어 1~2문장으로 요약하고 원문 링크를 붙인다. AWS 구성도를 그릴 때는 AWS 공식 아키텍처 아이콘을 사용한다. [AWS 아키텍처 아이콘](https://aws.amazon.com/architecture/icons/)
- 그림이 문제의 전제라면 자료와 채팅에서 문제 바로 앞에 다시 보여준다. 답변에 필요한 구성 요소, 상황, 값을 문제와 함께 적는다.

## 4. 반드시 지킬 수업 방식

1. 수업 자료에 학습 목표, 새 개념, 예제·그림, 확인 문제를 먼저 작성한다. 22주차부터는 상세 계획의 실습에 맞춰 입력·부하·실패 시점·관측할 값과 복구 후 확인할 상태를 포함한다.
2. 자료 링크와 함께 해당 범위 안에서 설명한다. 새 개념이나 문제를 추가할 때는 자료부터 갱신한다.
3. 자료와 같은 번호로 모든 확인 문제를 한 번에 제시한다. 한 문항 안에 여러 질문이 있으면 `1-1`, `1-2`처럼 하위 번호를 붙인다. 정답과 해설은 답변을 받은 뒤 공개한다.
4. 정답·부분 정답·오답·미응답을 실제 답변대로 기록한다. 결론과 근거의 정확성을 확인하고, 실습은 기대 결과와 실제 관측을 비교한다.
5. 평가 후 수업 자료에 해설을 반영하고 학습진도에 최초 점수, 보완 문제 결과, 오개념과 다음 행동을 기록한다. 수업 상태나 다음 행동이 바뀌면 이 문서도 갱신한다.
6. “ㅇㅇ 다음”처럼 짧게 이어가기 요청이 오면 기록의 다음 행동을 진행한다. 독학 결과는 사용자가 보고한 내용과 근거를 남긴다.

기본 실습 환경은 로컬이다. 향후 사용자가 실제 AWS 실습을 요청하면 기존 SAP 방식에 따라 계정 사용 범위와 예상 비용, 생성할 리소스와 정리 절차를 확인한다.

## 5. 현재 상태

- 2026-11-15에 60주 학습 계획을 정리했다. 완료 주차는 0/60이다.
- 1주차 첫 수업 최초 결과는 정답 5개, 부분 정답 1개다. 보완은 정답 1개, 부분 정답 1개다. 배열 요소의 기본값과 명시적 초기값을 구분했다. 4-2의 결과 표기와 빠진 `stock[0]` 값은 해설에 반영했다.
- 1주차 두 번째 수업 최초 결과는 정답 4개, 부분 정답 2개다. 보완 4-1은 1/1이다. 17,999원 주문에만 배송비가 붙으며 두 총액은 20,499원과 18,000원이라고 답했다.
- 1주차 세 번째 수업 자료를 제공했다. 확인 문제 1-1~3-2의 답변을 기다린다.
- 실습 기준은 Java·Spring Boot·PostgreSQL·Redis이며, RabbitMQ와 Kafka는 같은 이벤트로 각각 비교한다. 구체적인 버전은 첫 실습에 맞춰 확인하고 기록한다.

## 7. 완료와 복습 기준

- 일반 주차는 새로운 5문항 중 4개 이상에서 답과 이유를 확인하고 계획에 적힌 산출물과 마지막 회상 복습까지 확인하면 완료한다.
- 보완이 필요하면 다른 문제로 재확인하고 최초 평가와 보완 평가를 각각 남긴다.
- 과정 중에는 1주·3주 전 개념을 회상한다. 단계별 평가에서는 문제 풀이와 실습 결과를 모두 근거로 사용한다.
- 30주차에는 주문의 핵심 기술 통합을 평가한다. 37주차 분산 시스템, 43주차 MSA, 48주차 DevOps, 52주차 SRE, 59주차 Infra·복구 훈련에서 상세 계획의 검증 기준을 적용한다.
- 60주차에는 새 요구사항에 따른 설계, 59주차와 다른 장애의 재현과 복구, 데이터 정합성, SLO 측정 근거를 함께 평가한다.
