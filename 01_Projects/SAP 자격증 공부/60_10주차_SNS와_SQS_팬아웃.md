# 10주차 네 번째 수업 · SNS와 SQS 팬아웃

![AWS 공식 SNS 팬아웃 구성도](https://docs.aws.amazon.com/images/sns/latest/dg/images/sns-fanout.png)

그림은 하나의 SNS 토픽이 주문 처리 큐와 분석 큐에 같은 이벤트를 전달하는 예다.
이 수업에서는 분석 큐 대신 고객 알림 큐를 사용한다.

## 한 번 발행하고 여러 팀에서 처리하기

**SNS 토픽**은 발행자가 메시지를 보내는 주소다.
**구독**은 토픽의 메시지를 어느 대상으로 보낼지 설정하는 연결이다.
**팬아웃(fan-out)**은 토픽에 한 번 발행한 메시지를 여러 구독 대상으로 전달하는 방식이다.

주문 API가 `OrderCreated`를 SNS 토픽에 발행한다.
토픽을 구독한 배송 SQS 큐와 알림 SQS 큐에 각각 메시지가 들어간다.
배송 워커와 알림 워커는 자기 큐에서 메시지를 받아 독립적으로 처리하고 삭제한다.
배송 워커가 배송 큐에서 메시지를 삭제해도 알림 큐의 메시지는 남는다.

## 큐 하나를 여러 워커가 읽으면

배송 워커 A와 B가 같은 큐를 읽으면 둘은 배송 작업을 나눠 맡는다.
예를 들어 A가 주문 101을 처리하는 동안 B는 주문 102를 처리할 수 있다.
Standard 큐의 메시지는 재수신될 수 있으므로 중복 처리 방지는 여전히 필요하다.
서로 다른 팀이 모든 주문 이벤트를 각각 처리해야 한다면 팀별로 큐를 나누고 둘 다 같은 토픽을 구독시킨다.

## 큐에 메시지가 들어오려면

SQS 큐를 SNS 토픽에 구독시키고 큐 정책에서 그 토픽이 `sqs:SendMessage`를 할 수 있게 허용한다.
예를 들어 `aws:SourceArn` 조건에 주문 토픽 ARN을 지정한다.
토픽에 대한 발행 권한과 SNS가 대상 큐로 전송할 권한은 각각 확인한다.

## 공식 문서 핵심 요약

- SNS 토픽에 메시지를 한 번 발행하면 SNS가 구독 대상에 각각 전달한다. 각 팀이 모든 주문을 독립적으로 처리하려면 팀별 SQS 큐를 같은 토픽에 구독시킨다. [AWS 공식 팬아웃 구성](https://docs.aws.amazon.com/sns/latest/dg/welcome.html)
- SNS는 메시지를 구독 큐로 보내고 워커는 자기 큐에서 메시지를 꺼내 처리한다. 구독 설정과 함께 SQS 큐 정책에서 해당 SNS 토픽의 `sqs:SendMessage`를 허용해야 한다. [AWS 공식 SNS와 SQS 구독 설정](https://docs.aws.amazon.com/sns/latest/dg/sns-sqs-as-subscriber.html)

## 확인 문제

주문 API가 `OrderCreated`를 주문 SNS 토픽에 발행한다.
배송 큐와 알림 큐가 이 토픽을 구독하며, 별도 필터 없이 두 큐 모두 정상적으로 메시지를 받도록 설정되어 있다.

**1-1.** 주문 API가 이벤트를 한 번 발행하면 어떤 큐에 메시지가 들어가는가?

**1-2.** 배송 워커가 자기 큐에서 메시지를 삭제했다. 알림 워커가 멈춰 있었다면 복구 후 보존 기간 안에 자기 큐에서 같은 주문의 이벤트를 처리할 수 있는가?

**2-1.** 배송과 알림 워커가 같은 SQS 큐 하나를 읽도록 바꾸면 각 팀이 모든 주문을 하나씩 받아 처리할 수 있는가? 그 이유는 무엇인가?

**2-2.** 새로 연결한 분석 큐의 구독은 활성 상태지만 큐 정책에 SNS 전송 허용이 없다. 주문 API의 SNS 발행은 성공했다. 분석 큐에서 어떤 정책에 어떤 액션을 허용해야 하는가?

## 확인 문제 평가 · 2026-11-10

정답 3개, 오답 1개.

- **1-1 정답.** 주문 SNS 토픽을 구독한 배송 큐와 알림 큐에 각각 메시지가 들어간다.
- **1-2 오답.** 알림 워커는 복구 후 보존 기간 안에 자기 큐에서 메시지를 받아 처리할 수 있다. 배송 큐에서의 삭제는 알림 큐에 이미 들어간 메시지에 영향을 주지 않는다.
- **2-1 정답.** 같은 큐의 워커들은 메시지를 나눠 받는다. Standard 큐의 재수신 가능성과 별개로 두 팀에 이벤트를 각각 전달하려면 큐를 분리한다.
- **2-2 정답.** 분석 큐 정책에서 SNS 서비스의 `sqs:SendMessage`를 허용한다. 리소스는 분석 큐 ARN으로 지정하고 `aws:SourceArn` 조건에는 주문 SNS 토픽 ARN을 지정한다.

**1-2 보완 정답.** 질문의 주체인 알림 워커는 보존 기간 내에 복구하면 알림 큐에 남은 메시지를 처리할 수 있다고 답했다.
