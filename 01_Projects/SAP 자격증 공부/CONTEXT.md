## 4. 반드시 지킬 수업 방식

1. 먼저 해당 수업 자료 파일에 개념 설명, 예제, 확인 문제를 준비한다.
2. 자료 링크를 제공하고, 자료 범위 안에서 설명한다.
3. 사용자가 직접 답하도록 문제를 제시한다. 미응답 문제의 정답은 미리 공개하지 않는다.
4. 답변을 채점하되, 결론이 맞는 것과 이유가 정확한 것을 구분한다. 이유가 모호하면 짧게 교정한다.
5. 답변을 받은 뒤 자료에 해설을 반영하고 `학습진도.md`를 갱신한다.
6. 수업을 마치거나 다음 행동이 바뀌면 이 문서의 현재 상태도 함께 갱신한다.

사용자가 “수업 자료에 없는데”라고 지적한 이력이 있다. 새 개념을 채팅에서 먼저 가르치거나 자료에 없는 문제를 내지 않는다. 필요한 내용은 자료에 먼저 추가한다.

수업은 설명 → 예제 → 설계/확인 문제 → 채점·해설 → 복습으로 진행한다. 사용자는 “ㅇㅇ 다음”처럼 짧게 다음 단계 진행을 요청할 수 있다. 그때는 다음 자료를 준비하고 바로 수업을 진행한다.

실제 AWS 실습 전에는 사용 가능한 계정과 허용 비용을 확인하고 생성할 리소스, 예상 비용, 삭제 절차를 안내한다. 파일 작성 요청을 AWS 계정 조작의 승인으로 해석하지 않는다.

### 이미 보충 설명한 사항

- Multi-AZ는 AZ 단위 장애에 대비하는 구성이다. 리전 전체 장애 대비는 별도로 설계한다.
- 단일 AZ 장애가 모든 AWS 서비스의 중단을 뜻하지는 않는다. 해당 AZ에 의존하는 구성요소가 영향을 받을 수 있다.
- EC2 게스트 운영체제 패치는 고객 책임이다. 모든 AWS 서비스의 기반 OS를 고객이 패치하는 것은 아니다.
- S3의 기반 OS는 AWS가 관리한다. 누가 회사 파일에 접근할지 결정하고 설정하는 일은 고객 책임이다.
- 서버 대수 확대, 수요에 따른 확대·축소, 장애 격리는 관련이 있지만 구분하여 판단한다.

1번 도메인 오타(porta→portal)와 페이지 응답 상대 생략은 보완했다. DNS 역할과 이전 정확한 흐름 설명을 함께 반영했다.
3번에서 NAT의 내부 시작 연결·응답과 외부 시작 새 연결 제한을 정확히 설명해 이전 이유 오류를 독립적으로 재확인했다.
4-1은 앞뒤 TLS 보호 구간을 정확히 구분했다.
4-2는 ALB→EC2를 TLS로 바꾸는 방향은 맞으나 “보안 규칙으로 HTTPS 설정”이라는 표현을 보완했다.
자료에 웹 서비스의 인증서·TLS 수신 설정과 ALB HTTPS 전달 및 포트 허용을 나눈 그림을 추가했다.
2026-11-01 보완 6-1·6-2 모두 정답이다.
EC2에 TLS 설정이 없으므로 실패하고 EC2 웹 서비스에 TLS 설정을 추가해야 한다고 정확히 설명했다.
구체적으로 인증서·비밀 키로 HTTPS 수신하도록 구성하는 것이라고 해설에 정리했다.
초기 점수는 유지하고 보완 확인을 별도로 기록한다.
[마지막 회상 자료](16_3주차_회상_복습.md)를 준비했다.
다음은 회상 1-1~3-2에 대한 답변을 받아 평가하는 것이다.
문제는 review.example.com:8443/start의 DNS·포트·경로와 앞HTTPS8443/뒤HTTPS9443의 TLS 연결 및 보안 규칙의 역할과 10.8.2.128/25 범위 및 NAT 연결 시작 방향을 묻는다.
미응답 해설이나 완료를 추정하지 않는다.
이후 마지막 회상 복습까지 확인해 주차 완료를 판단한다.
수업이 늘어 이번 주는 6회 구성이며 시간은 실제 학습 시간에 맞춰 조절한다.
사용자가 TLS의 인증서 확인 범위를 질문해 13 자료에 도메인·신뢰 경로·유효 기간·서명 기반 비밀 키 보유 확인을 보충했다.
공개 키·비밀 키 상세는 17주차 암호화 심화에서 다룬다고 안내했다.
추가 질문으로 12 자료에 Public/Private NAT Gateway 비교 표와 두 경로 그림을 추가했다. Public은 Elastic IP 및 인터넷 게이트웨이를 통한 인터넷 연결에 사용하고 Private은 다른 VPC·회사 내부망 통신에 사용하며 Elastic IP를 연결할 수 없음을 설명했다. 둘 다 외부 임의 새 연결을 허용하지 않는다. Public도 사설망에 사용할 수 있으며 그때는 사설 IP를 사용하는 점을 보충했다. 해당 질문 이후 HTTP/HTTPS·포트 자료를 제공했다.
실제 AWS 계정 조작은 하지 않았다.

2주차 완료: 2026-11-01.
최초 종합 확인은 정답 3문항과 부분 정답 1문항 및 미응답 1문항으로 유지한다.
다른 상황의 보완 문제 A·B에서 2/2로 재확인했다.
마지막 회상 답변에서 두 정책과 프로파일 및 루트 최소 권한과 PutObject 및 SDK의 만료 전 갱신과 유출 한계를 설명했다.
신뢰 정책은 “누가 접근하는가”보다 “누가 역할을 맡는가”로 정확히 표현하도록 보완했다.
회상 2번의 FIDO/TOTP 차이 및 3번의 대상 범위는 생략되었으나 앞선 보완 A·B와 설계 연습에서 정확히 답한 근거를 함께 반영했다.
자료에 생략된 설명과 마무리 그림을 추가했다.
이 과정을 근거로 2주차 완료 처리했고 최초 종합 확인을 5/5로 바꾸거나 회상에 점수를 추정하지 않았다.

주요 학습 선호는 문장마다 줄바꿈과 불필요한 쉼표 제거 및 개념·보완 설명의 그림 첨부다.
완료 주차는 2/32다.
1주차 완료 기록과 과거 부분 정답 기록은 유지한다.
