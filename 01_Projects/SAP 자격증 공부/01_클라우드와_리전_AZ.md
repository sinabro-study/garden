# 1주차 첫 수업: 클라우드, 리전, AZ

예상 30~45분 · 계정과 유료 리소스 불필요

## 오늘의 목표

클라우드의 의미, 리전과 AZ의 차이, 단일 AZ 장애에 대비하는 이유를 설명한다.

## 개념

클라우드는 서버·저장소·데이터베이스 같은 IT 자원을 필요에 따라 이용하는 방식이다. 필요한 양을 조절하고 사용량에 따라 비용을 지불할 수 있지만, 서비스별 과금 방식과 약정 조건은 다르다.

리전(Region)은 AWS 인프라가 위치한 지리적 영역이다. 리전을 고를 때는 사용자와의 거리, 데이터 보관 규정, 서비스 제공 여부, 비용을 확인한다.

가용 영역(Availability Zone, AZ)은 리전 안에서 장애 격리를 위해 구분된 인프라 영역이다. 하나 이상의 데이터센터로 구성된다. 여러 서버를 같은 AZ에만 두면 그 AZ 장애에 함께 영향을 받을 수 있다. 여러 AZ에 나누는 것은 AZ 장애 대응의 출발점이다.

여러 AZ 배치만으로 전체 서비스가 자동으로 고가용성이 되지는 않는다. 요청 분산, 정상 서버로의 전환, DB 복제와 장애 조치도 함께 설계해야 한다. 리전 전체 장애에 대한 대비는 별도 요구사항이다.

공동 책임 모델: AWS는 클라우드 인프라의 보안을 맡고, 고객은 자신이 사용하는 서비스에 맞게 권한·데이터·설정 등을 관리한다. EC2 운영체제 패치처럼 고객이 맡는 일도 있고, 관리형 서비스에서는 AWS가 더 많은 운영 업무를 맡는다.

## 생각해 볼 예시

쇼핑몰 웹 서버 두 대와 DB 한 대가 같은 AZ에 있다. 웹 서버 한 대만 고장 나면 다른 서버를 사용할 수 있지만, AZ 전체에 장애가 나면 세 대가 동시에 영향을 받을 수 있다. 서버 대수와 장애 범위는 서로 다른 문제다.

## 확인 문제 — 번호와 이유를 함께 답하기

1. 같은 AZ에 웹 서버 3대를 둔 구성과, 2개 AZ에 웹 서버를 나눈 구성 중 AZ 장애에 더 유리한 구성은 무엇인가? 이유는?
2. 리전과 AZ는 어떤 관계인가? 각각 한 문장으로 설명해 보자.
3. EC2에서 운영하는 애플리케이션의 IAM 권한 설정은 AWS와 고객 중 누구의 책임인가? 이유는?

이 문제는 학습용 자체 제작 문제이며 실제 시험 난도를 대표하지 않는다. 정답은 답변 제출 후 해설한다. 3문항 확인은 첫 수업 점검이며, 주차 완료 시 별도의 5문항으로 재평가한다.
